# 0009 — A wiki for humans, and the agent that keeps it

- Status: accepted
- Date: 2026-10-29
- Decided by: the implementing agent, within the maintainer's decisions (a documentalist launched from the harness; a wiki for people, consumable from the repository, apart from the agents' memory)

## Context

The memory under `.ways/knowledge` is short facts for agents. People also need to learn the project: how to start, how to do a task, what the pieces are, why. Without a tool, that documentation rots silently. An LLM-written overview handed to an agent as truth is worse than none, so the two must not mix.

The analysis (section 6) proposed `ways docs`, a worktree per run, a `task.json` with a write scope, a `wiki.stale` event, executed ```` ```sh test ```` blocks and a draft/reviewed status. Most of that is ceremony the lean harness does not have anymore (there are no tasks, and worktrees are optional).

## Decision

- **Where and what.** `docs/wiki/` in plain Markdown, no generator (GitHub renders it), Diátaxis folders `tutorials/`, `how-to/`, `reference/`, `explanation/` that appear with their first page, and an `index.md`. Frontmatter: `title`, `kind`, `sources` (repository paths the page documents), `source_hashes` (path → hash when written) and `reviewed` (date).
- **Freshness is by hash, computed from the working tree.** A file source hashes like `git hash-object`, cut to 12 hex characters; a page is stale when any source differs. A folder source (trailing `/`) hashes the *names* of the files under it: adding, removing or renaming a file stales the page, editing one does not. A page about a module is not worth CI noise on every edit; it cites the files it describes to follow their content. Chosen over `git rev-parse HEAD:<path>`, which cannot see uncommitted work.
- **Hashes are written by ways.** An agent cannot compute them reliably and should not vouch for itself. `ways wiki update --stamp <page>...` records the current hashes and the date for pages a person has checked; after an agent run ways stamps every page the agent changed. A stamp is a tripwire, not a proof: it says "someone looked at this page against these sources".
- **Four actions** (budget 33 → 37): `wiki init`, `wiki check`, `wiki stale`, `wiki update` (also `--stamp`, `--dry-run`, `--agent=`). `stale` is `check` restricted to freshness and costs no code; it was asked for by name. Stamping is a mode of `update` to avoid a fifth action.
- **`wiki check`** validates frontmatter and folders, internal links and `#anchors` (external links are left to a link checker in CI), that sources exist, freshness, that every page is reachable from the index, command examples, and coverage (`.ways/wiki.json` `scope`: folders that some page must cite, commands that some page must mention). A repository without a wiki passes, so the CI step is safe everywhere. Examples in blocks marked ```` ```sh ways-check ```` are checked statically against the command registry (the command, its action and each `--option` must exist); they are never executed, because running text from a page is not worth the risk for what it adds.
- **`wiki update` launches the documentalist.** ways builds a deterministic brief from `check` (stale pages and which sources, gaps, broken links, existing pages) and the role text, then starts `claude -p`, `pi -p` or any command (brief on stdin) as a new process in the repository. Claude Code gets `--permission-mode dontAsk` and `--allowedTools` limited to `Edit`/`Write` under `docs/wiki/**`, reads, `ways wiki check` and read-only git; edits to `.ways/**`, commits and the web are denied; if ways is installed it also adds, with `--settings`, a PreToolUse hook that runs ways' guard for every write and shell call. pi gets `read,grep,find,ls,edit,write` (no shell). With nothing stale, missing or broken, no agent starts.
- **The run is judged afterwards, not trusted.** ways snapshots the uncommitted paths outside the wiki (with content hashes) and HEAD, and compares after the agent exits: anything new or changed outside `docs/wiki/`, or committed outside it, fails the run, names the paths and stamps nothing. ways does not revert: the tree may hold the person's own work, so it prints how to undo instead.
- **No worktree, branch or PR.** The wiki is edited in place and the person reviews the diff of `docs/wiki/` and commits. This is the least ceremony; isolation is the person's choice (run it from a worktree).
- **Role.** `documentalist` is a portable role (`assets/adapters/roles/documentalist.md`, six lines, like the reviewer) that the adapters also install as a subagent. A session that `wiki update` launched has `WAYS_ROLE=documentalist` in its environment, which is how the guard, the commit hook and the event log know. It shows on the board (a `role` field on events; a badge on the card) from a session recorded on the bus.
- **Separation from the memory is mechanical, and tested:** (1) context, the memory index and search, and staleness ignore `docs/wiki`; (2) the guard refuses the role's writes outside `docs/wiki/` (and its `WAYS_DISABLE=1`, or unsetting `WAYS_ROLE`, which the commit hook reads) and pi's extension asks the guard about every call of such a session; (3) the commit hook refuses its commits outside `docs/wiki/` and adds `Harness-Role: documentalist`, and `ways check --history` flags a commit with that trailer that leaves the wiki, which does not depend on the hook having run; (4) `ways memory check` fails a concept whose `sources`, `paths` or links point into `docs/wiki/`. The wiki may cite the memory.

## Consequences

- Changing a file that a page cites makes `ways wiki check` fail until the page is caught up or re-stamped. That is the point, and the cost: cite the narrowest files, use folder sources for module maps, and let `ways wiki update` do the catch-up. The ways repository runs `wiki check` in its CI.
- A stamp can be given without reading. We accept that: the alternative (proving a page is true) is not decidable; the date and the git history show who stamped it.
- `docs/wiki/reference/commands.md` is generated from the command registry by a test (`UPDATE_README=1`), so the reference cannot disagree with the program; its examples are checked by `wiki check` against that same registry.
- The Claude Code invocation was written from `claude --help` on the development machine, and pi's from the flags the reviewer preset already uses; both are exercised in tests with fake agents and neither has been run against the real binary in this change. If a flag turns out to differ, `ways wiki update --dry-run` shows the command and `--agent="<command>"` replaces it.
- Not done: a `wiki.stale` event or inbox nudge when a work closes, executing example blocks, external link checking, symbol-level sources (`path#Symbol`), and a draft/reviewed status. Each can be added when it earns its place.
