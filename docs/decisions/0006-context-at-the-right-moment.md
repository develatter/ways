# 0006 — Context at the right moment, and a local event bus

- Status: accepted
- Date: 2026-10-29
- Decided by: the implementing agent, within the maintainer's brief (F3: hooks inject a short packet, path rules from memory, AGENTS.md as a map, JSONL events; the agent is not led by the hand)

## Context

After 0.3 lean the agent only learned the state of its work if it ran `ways status`, and the memory of an area only if it asked. Claude Code documents "what must always happen goes in a hook" and path-scoped rules (`.claude/rules/*.md` with `paths:`); pi has an extension API but no command hooks. The analysis (F3) asked for `ways hook <event>`, `ways context --brief` under 6,000 characters, rules from memory, an `AGENTS.md` of at most 100 lines and an event log under the Git common directory, with a hook p95 under 100 ms.

## Decisions

- **One entry point, one thin provider layer.** `ways hook <SessionStart|UserPromptSubmit|PreToolUse|PostToolUse|Stop|SessionEnd> --agent=<claude|pi|codex|cursor>` reads the agent's JSON on stdin. Only `src/hooks/providers.ts` knows payload and output shapes; contract tests pin them with fixtures of real payloads. Claude Code calls it through the managed `.ways/hooks/agent-hook` wrapper (it finds the CLI like the Git hooks do and says nothing when there is none); pi through the ways extension, which maps `session_start`, `before_agent_start`, `tool_call`, `tool_result`, `agent_end` and `session_shutdown` onto the same events. Codex and Cursor get the Claude format and no installation (best effort).
- **State, not procedure.** The brief says what is active, each criterion's result, what the last `ways done` reported failing (a headline per item and its last three output lines), what waits on whom, one `Next:` line and up to five memory facts for the code in play. No step lists, nothing from `AGENTS.md`. SessionStart injects it whole; UserPromptSubmit injects only the sections whose text changed since this session last saw them, plus a one-line "cleared" note for a section that disappeared, and stays silent otherwise. A memory fact is injected once per session (again after `compact` or `clear`).
- **Which memory.** Concepts whose `paths` cover a file touched in the session (newest first), then uncommitted files, then files the work changed; more specific globs first, then fresh before possibly stale. Stale concepts are shown with a marker, never hidden. Each fact carries the concept path for detail.
- **Stop reminds once, and asks the right party.** A blocker the agent can act on (the last `ways done` failed on HEAD, a required review) blocks the stop once per blocker and session (`decision: "block"`), never when `stop_hook_active` is set. One only the human can resolve (approval) goes to the human as `systemMessage` and never keeps the agent going. Uncommitted or unevaluated work is not a blocker: Stop fires at the end of every turn, and an agent answering a question must not be pushed back into work.
- **The guard came back narrower.** 0003 removed the 0.2 PreToolUse guard because the commit hook already refuses record tampering. The brief asked for it again; it now refuses only (a) a tool call that writes, moves or deletes `.ways/work/**` (every mode: the same rule as the commit hook, just earlier, so the agent does not waste a round trip) and (b) in `enforce` mode, a shell command that switches the commit hooks off (`WAYS_DISABLE=1`, `core.hooksPath`). Shell commands are read with a small tokenizer that follows `cd`, ignores `2>&1`, `>&2` and `/dev/null`, and allows reads. Any internal error fails open: the commit hook and CI remain the guarantee.
- **Path rules for Claude Code.** One `.claude/rules/ways-<concept>.md` per current concept with `paths:`, carrying the fact and a "generated, do not edit" marker. They are committed (they work without hooks, on any checkout) and regenerated by `ways remember`, `ways memory index` and adapter installs; `ways memory check` warns when they drift; only marked files are ever removed. pi has no path rules, so its extension appends the memory of a newly touched file to the tool result instead (once per concept and session).
- **`ways context` returns** (0003 had merged the 0.2 `context` into `status`): `status` is the human's view, `context` the agent's bounded packet (`--brief` caps it at 6,000 characters; `--json` for orchestrators; `--session=<id>` ranks memory by what that session touched).
- **Skills only for the optional.** The `status` command/skill is gone: the hooks bring the status. `outcome` and `remember` are skills in `.claude/skills/` (Claude Code merged commands into skills and does not read `.agents/skills`) and in `.agents/skills/` (read by pi and Codex; both adapters write it byte for byte the same, so it is shared).
- **`AGENTS.md` is a map**: what the project is, where things live, commands, conventions, and five lines on ways.
- **Event bus.** `<git-common-dir>/ways/events/<session>.jsonl`, schema `v: 1` (see [docs/EVENTS.md](../EVENTS.md)), metadata only (no prompts, no file contents, no command output), one `appendFileSync` per line capped at 4 KiB, session files rotated at 1 MiB to unique names, the directory pruned at SessionStart. It feeds the board (F5) and review provenance (F4); nothing reads it for decisions yet except "paths touched in this session".
- **Performance.** A hook is a Node process per event. On the hot path: no ajv, no yaml, `node:crypto` and `node:child_process` loaded only when needed, no ICU collation (`localeCompare` cost ~15 ms per process), stdin/stdout through descriptors (streams load `net`), and caches in `<git-common-dir>/ways/context/` keyed by HEAD, the index and the concept files, so git and yaml run once per commit or memory edit. Claude Code starts the guard only for calls an `if` permission rule says could matter (`Edit(**/.ways/work/**)`, `Bash(*.ways/work*)`, `Bash(git commit *)`, ...), and logs edits with an `async` hook; pi's extension applies the same filter in JavaScript before spawning anything.

## Consequences

- Measured on the development machine (Node 26, a slow shared host where `node -e 0` takes p50 ≈ 62 ms, p95 ≈ 80 ms): `ways hook PreToolUse` over 200 runs p50 ≈ 90 ms, p95 ≈ 112–121 ms; UserPromptSubmit and SessionStart with a warm cache p50 ≈ 105 ms, p95 ≈ 130–135 ms; the first hook after a commit rebuilds the memory cache (~230 ms). The 100 ms p95 target is **not met** on this host; ways adds ~25–30 ms over a bare Node start. In Claude Code the guard and the edit log no longer run on ordinary tool calls, so the per-call cost the agent sees is near zero; the prompt and session hooks remain. Bundling the hook path into one file (an esbuild step) is the next lever (~6–8 ms) and was not done here.
- A sample working session injected ~4,900 characters in total (2,640 at start, then only deltas); a question-only session ~2,700.
- `if` rules are best-effort in Claude Code: when it cannot tell, the hook runs anyway; when a pattern misses an exotic command, the commit hook still refuses the commit. The `if` syntax with a leading `*` and pi's `before_agent_start` `message`, `tool_result` content rewrite and `sendMessage(..., { triggerTurn: true })` follow the docs read on 2026-10-29 but were not exercised against a live agent; the contract tests drive the real extension code with a fake pi API.
- Rules are committed derived files: a concept edited by hand without `ways memory index` leaves a stale rule until someone runs it (warned by `ways memory check`).
- Lifecycle events from the CLI itself (`done`, `review`, `approve`) and inbox questions (`ways ask`/`block`) are not in the bus yet; the brief's "Waiting on" section is where they will appear.
